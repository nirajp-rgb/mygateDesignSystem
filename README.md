# MyGate Design System (MDS)

Design tokens, component documentation and the token pipeline for the MyGate independent app.

Token names match the Figma file **Foundation (New)** and the code. `Color/Content/action` in Figma is `--color-content-action` in CSS.

## What's in here

```
tokens/                  Source of truth. Edit these (or import changes into them).
  primitives.json        Raw values: Color, Dimension, Font Size, Font Weight, Font Family
  layout.json            spacing, borderRadius, sizing (icon + component), borderWidth, elevation, typography
  semantic-light.json    Color/Surface, Content, Border, Accent → primitives, Light mode
  semantic-dark.json     The same tokens, Dark mode
  $themes.json           Light and Dark themes (Tokens Studio format)
  $metadata.json         Token set order (Tokens Studio format)
dist/                    Generated by "npm run build". Committed, so apps can use it without building.
  tokens.css             CSS variables: :root (light) + [data-theme="dark"] + prefers-color-scheme
  tokens.light.json      Every token, resolved, Light
  tokens.dark.json       Every token, resolved, Dark
docs/index.html          The documentation site (Overview canvas + Documentation view)
scripts/                 build, check and import (Node 18+, no dependencies)
exports/                 Drop exports from the docs site here. Ignored by git.
```

Tokens use the [W3C design tokens format](https://tr.designtokens.org/format/): every token has `$type` and `$value`, and aliases are written `{Color.gray.600}`. Notes about changes from Figma live in `$extensions.mds` (`status`: `added`, `changed` or `deprecate`).

## Setup

You need Node 18 or newer. There is nothing to install.

```sh
npm run check   # validate: every reference resolves, no name clashes, contrast report
npm run build   # write dist/
```

To view the docs, open `docs/index.html` in a browser, or go to the hosted site at https://nirajp-rgb.github.io/mygateDesignSystem/. The site is published by `.github/workflows/pages.yml` on every push to `main`. The built tokens are hosted too, at `/dist/tokens.css`.

## Making a change

1. Open `docs/index.html`, go to **Overview**, and change what you need: remap a semantic token to a different primitive, change a primitive colour, or remap a component size.
2. Click **Copy tokens** (bottom of the left panel) and save the clipboard to a file in `exports/`, for example `exports/border-dark-fix.json`.
3. Apply it to the token files and rebuild:
   ```sh
   git checkout -b tokens/border-dark-fix
   npm run import -- exports/border-dark-fix.json
   npm run build
   ```
   `import` prints every change it made, for example `semantic-dark: Color/Border/dark {Color.gray.600} → {Color.gray.500}`.
4. Add a line to `CHANGELOG.md`, commit `tokens/`, `dist/` and the changelog, and open a pull request. Paste the import summary into the description.
5. CI runs `npm run check` and confirms `dist/` was rebuilt.

You can also edit the JSON in `tokens/` directly. Run `npm run build` afterwards.

## Syncing with Figma

The `tokens/` folder is in [Tokens Studio](https://tokens.studio) format: token sets plus `$themes.json` and `$metadata.json`. In the Tokens Studio plugin, add a GitHub sync provider pointing at this repo, branch `main`, folder `tokens`. Designers can then pull tokens into Figma variables, or push Figma changes as a pull request.

The aim is one set of names across Figma, these files and the code. Until the Figma file is cleaned up, some tokens here differ from Figma on purpose. The **Token structure** page in the docs lists every proposed change.

## Using the tokens in code

```html
<link rel="stylesheet" href="dist/tokens.css">
```

```css
.button-primary {
  background: var(--color-surface-action-primary);
  color: var(--color-content-on-light);
  height: var(--sizing-button-medium);
  border-radius: var(--border-radius-200);
  font: var(--typography-body-large-bold);
}
```

Switch modes with `data-theme="dark"` on `<html>`. Without the attribute, the device setting decides.

For native apps or the server-driven UI, read `dist/tokens.light.json` and `dist/tokens.dark.json`. They are flat maps from the Figma name to the final value.

## Rules

- Components use semantic tokens only, never a primitive or a hex value.
- Yellow (`Color/Surface/action-primary`) is for the one primary action per screen.
- ClearBlue (`action-secondary`, `Content/action`, `Border/action`) is for links, controls and selection.
- Secondary actions, navigation and segmented controls stay neutral.
- Component sizes use `sizing/{component}/{size}`, each an alias to a `Dimension` primitive.

## Known issues

`npm run check` reports these contrast warnings today:

- **Dark mode field borders:** `Border/dark` (gray/600) is 2.1:1 on `Surface/primary`. It needs 3:1, so try gray/500.
- **Count badges:** white on `Surface/nudge` (red/400) is 3.7:1 for 12px text. Mapping nudge to red/600 would fix it.
- **Meta text:** `Content/tertiary` (gray/500) is 3.6:1. Use it only for timestamps and meta, never for sentences.
- **Disabled labels:** 1.9:1 in light mode. Disabled text is exempt from WCAG, but it may be too faint.
- **Status text in dark mode:** `Content/positive`, `negative` and `info` share the primitive of their `Border` token. The 400 shades are 3.1–3.8:1 for success and info. Adding a 300 step would fix text and border together (see `ROADMAP.md`).

## Not done yet

See [ROADMAP.md](ROADMAP.md) for the full plan. The short list:


- The docs site still carries its own copy of the token values. A later step is to make it read `dist/tokens.light.json` and `dist/tokens.dark.json`, so the repo is the only source.
- `Body Large` line height (20px in the Figma style, 24px on the Figma docs page) needs a decision.
- Dark mode action and status text uses the 200 shades. A 300 step per colour would keep them recognisably coloured.
